# Промпт: таймзона записи и напоминаний (Иркутск + dual display)

## Контекст
SaaS «Все клиенты здесь» (allyourclients.ru). Расписание ведётся в поясе **календаря** (по умолчанию `Asia/Irkutsk`, UTC+8). Клиент может быть в другом поясе.

## План реализации
1. **Site TZ** — `TIMEZONE=Asia/Irkutsk`, метки в UI/TG.
2. **Calendar TZ** — поле `calendars.timezone`; слоты и reminders в поясе календаря.
3. **Dual display** — клиенту показывать локальное время (browser `Intl` → `bookings.client_timezone`).
4. **Absolute reminders** — `booking_starts_at` в поясе календаря, сравнение в UTC (без хранения отдельного TIMESTAMP пока).

## Инцидент
Консультация уже прошла, но Telegram-напоминание «через 1 час» — слот трактовался как Moscow при wall-clock Иркутска.

## Критерий готовности
- Напоминание «за 1 час» уходит за ~1 час до слота по поясу календаря.
- После начала консультации такое сообщение не отправляется.
- В UI/TG видно пояс специалиста; при другом поясе клиента — «у вас: …».
- Prod `.env`: `TIMEZONE=Asia/Irkutsk` (код-дефолт не перебивает старый env).
